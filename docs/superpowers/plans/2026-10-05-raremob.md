# RareMob Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new addon, RareMob, that pins rare and rare elite spawns on the world map and the minimap, plays a sound when a living rare is near, and lists the zone's rares with when each was last seen on WoW Forever.

**Architecture:** A Node build reads vMaNGOS's SQLite dump into three generated Lua data files (rares, and spawns per continent in world yards); a bake turns players' saved variables into a fourth. In game, `Rares.lua` merges the database with the player's own and baked sightings into one view (per continent, every pin place in world yards; per zone, the list rows). `Spotter.lua` looks at nameplates, target and mouseover, records sightings and keeps the set of rares near now; `Alert.lua` plays the sound; `WorldMap.lua` and `MinimapPins.lua` draw `Pins.lua` pins with GatherMap's placement maths (`Geometry.lua`); `List.lua` is the zone window in BossLoot's frame.

**Tech Stack:** WoW Lua (5.1-flavoured) for the addon, Lua 5.4 and the repo's spec runner for tests, Node 24 (`node:sqlite`, `node:test`) for the build and bake, PowerShell for packaging.

**Spec:** [docs/superpowers/specs/2026-10-05-raremob-design.md](../specs/2026-10-05-raremob-design.md)

## Global Constraints

- `## Interface: 11509, 16001`; `## SavedVariables: RareMobDB`; installed to `_classic_beta_`.
- Self-contained: code is copied from BossLoot, GatherMap, LFGBoard and FishScale, never shared across folders.
- Every game call goes through `ns.Guarded`; a missing call turns its feature off quietly.
- Commands: `/rm` (and `/raremob`); bare `/rm` opens the list; `/rm probe`, `/rm settings`, `/rm minimap`, `/rm help`.
- Saved: `RareMobDB.sightings[id] = { name, level, elite, count, last, places = { { map, x, y, time }, ... } }` (at most 20 places, newest kept), `RareMobDB.recorder` (random id, made once), `RareMobDB.settings`.
- Settings, all on by default, pin size 14: Show pins on the world map; Show pins on the minimap; Show rares only in the database; Alert sound; Pin size (slider); Show the minimap button.
- Alert: `PlaySound(SOUNDKIT.RAID_WARNING)`, fallback id 8959; once per rare id per 5 minutes; never while `IsResting()`.
- Gone: no nameplate, not target or mouseover, for 30 seconds; or dead.
- Words: tooltip "Rare" / "Rare elite", "Last seen 3 days ago", "Seen on WoW Forever", "From the classic database, not seen on WoW Forever yet"; list "never".
- The build fails loudly on an empty result. Data: patch 10 (1.12) rows, as BossLoot filters them.
- The main session commits; this plan's executor does not. Root `README.md` is not touched.
- `tools/draw-icons.mjs` is shared with a concurrent agent: additive lines only, re-read just before editing, no other addon's `.tga` may change.

## Review Focus

1. **A rare seen again and again in one encounter** (nameplate, then target, then mouseover, every few seconds): it must count once and add one place, not dozens. Pinned in Task 4 ("counts a rare once while it stays near").
2. **A sighting of a rare the database does not have**: it must still pin, list and tooltip from the sighting alone. Pinned in Task 3 ("sighting only") and Task 6 ("a sighting with no database spawn gets a pin").
3. **The player's own recorder baked into the release**: its sightings must not count twice. Pinned in Task 3 ("own baked copy left out").
4. **A zone the client cannot place** (whole-world map, a city with no corners): no pins, an empty list, no error. Pinned in Task 6 ("nothing on a map it cannot place") and Task 8 ("an empty list where the map has no place").
5. **The world map loading after RareMob, or not at all**: attach when `Blizzard_WorldMap` loads; a row click on a client without the map does nothing harmful. Pinned in Task 6.
