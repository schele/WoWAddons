# BossLoot Redesign: Maps, Boss Portraits, New Layout

**Date:** 2026-09-26
**Status:** design approved in conversation ("yes"); the user asked for the
spec, plan, build, review and merge to run without further stops.
**Builds on:** `2026-09-26-bossloot-design.md` (data, filters, commands and
behaviour not mentioned here are unchanged).

## Purpose

The first BossLoot window works but is three plain columns on a see-through
background. This redesign:

1. makes the window **opaque** and readable over any scenery,
2. replaces the layout with a **rail, boss list, boss page** design,
3. shows **boss portraits** (round, in the list) and a **3D model** (on the
   boss page), and
4. adds a **map** of each instance with numbered boss pins.

## What the client offers (probed in game)

- No dungeon maps: scanning `C_Map.GetMapInfo` for map type 4 finds none,
  so there is no map art or map data to borrow. The map is generated.
- `SetPortraitTextureFromCreatureDisplayID` exists (round creature portraits
  from a model ID), and `PlayerModel:SetDisplayInfo` exists (3D models from a
  model ID). vMaNGOS has every boss's model ID (`creature_template.display_id1`).

## The window (layout C)

About 860 by 520, movable, remembers its position, closes on Escape, as
before.

- **Background.** A solid dark texture drawn by the addon over the whole
  frame, under a border. The old window relied on the dialog backdrop, which
  is translucent (and may not load at all); the new one is opaque whatever
  the backdrop does.
- **Instance rail** (left, about 170 wide). Dungeons and Raids tabs, the
  search box with "Search..." placeholder text, and the instance names, each
  with its level range. Right-click hides an instance, as before.
- **Boss list** (middle, about 230 wide). One row per boss: a round portrait,
  the boss's number (the same number as its map pin), and its name. Wing
  headings as before. The notable entries show a bag icon (from trash) and a
  chest icon (chests and objects) where a boss has a portrait.
- **Boss page** (right, the rest).
  - **Header**: the boss as a slowly turning 3D model, its name, and the
    instance (and wing, if any) under it.
  - **Map inset**: a small map at the top right of the header, this boss's pin
    highlighted. Clicking it opens the **full map** over the boss page, with
    every pin numbered and clickable; clicking a pin selects that boss and
    closes the map. A close button or Escape-free click on the header returns.
  - **Loot grid**: item tiles in two columns (icon, name, type or source line,
    chance), scrolled with the mouse wheel, with a "▼ N more" line when more
    tiles are below than fit.

For the notable entries the header shows the bag or chest icon instead of a
model, "From trash" or "Chests & objects" as the title, and the map inset has
no pin highlighted.

**Fallbacks.** No portrait function: the list uses a skull icon. No model
function or no model ID: the header shows the round portrait instead. A boss
with no model ID (a chest-only row such as "Ring of Law: Arena Spoils"): the
chest icon. Missing templates keep working (fonts set on the plain fallback
frames).

**Also fixed while here** (deferred minors from the first review): the loot
column's missing "more below" hint, template fallbacks that would have been
unusable, and a one-letter search showing "No matches" (a search needs two
characters; under that the normal list shows).

## The map

Generated by the build script from the vMaNGOS database, one per instance.

**Revised after the first in-game look** (the dot map read poorly): the map
is a floor plan.

**Shapes.** Every creature spawn as a disc of its wander radius (capped at 20
yards), every game object as a point, and every patrol joined point to point
into a line ( per spawn,  per
creature,  for escorts; a step over 80 yards is a jump and
is not joined).

**Bounds.** The box around the shapes, ignoring the outermost 1% on each axis,
widened for any boss standing within a quarter of the map's size past that
edge (its room would otherwise be cut off), plus a 10-yard margin.

**Projection.** Seen from above with north up: screen right is world -y,
screen down is world -x.

**Grid.** Square cells of at least 4 yards, at most 200 across the longer
side. Shapes are marked on the grid, then closed up: grown twice to bridge
gaps, shrunk once; floor areas under 12 cells dropped; enclosed holes of up
to 10 cells filled.

**Pins.** A boss's pin is its first spawn on the map, or its chest's for a
chest-only boss, as fractions of the map. A boss outside the map by more
than half a cell gets no pin (and the build warns): a pin clamped to the edge
would sit beside a room that is not drawn. Summoned bosses have no spawn and
no pin.

**Data.** Each instance gains  (0-based): each row's floor as runs. Each boss gains
 and  when it has them.

**Drawing.** The map view draws each run as one strip of texture in the floor
colour, over the floor grown by one cell each way (worked out in the addon)
in a lighter colour, which leaves an outline. A few hundred strips per map;
strips are pooled, and only redrawn when the map or the view's size changes.


## Code layout

| File | Change |
|---|---|
| `tools/lib/map.mjs` | New. Points to grid, bounds with trimming, bands, pin projection. Pure |
| `tools/lib/db.mjs` | Spawn and waypoint positions on a map; a creature's or object's first spawn position |
| `tools/lib/instance.mjs` | Adds `display` and `pin` per boss, and `map` per instance |
| `tools/lib/lua.mjs` | Writes the new fields |
| `List.lua` | Multi-column grids (`columns` option) and the "more below" line |
| `Portrait.lua` | New. Round portrait on a texture, 3D model on a model frame, with fallbacks. Guarded |
| `MapView.lua` | New. Draws a map (cells and pins) into a frame of any size; pin clicks |
| `Window.lua` | Rewritten for layout C. The pure entry builders and selection logic stay |
| `BossLoot.toc` | Adds `Portrait.lua` and `MapView.lua` |

## Testing

- Build script (node:test): grid cells and bands from points, trimming a stray
  point, pin projection and clamping, a summoned boss with no pin, display IDs,
  waypoints included, and the Lua output of the new fields.
- Addon (Lua specs): multi-column list layout and scrolling by rows, the
  "more below" line; portraits and models with each fallback; the map view's
  cells and pins, pin highlighting and clicks; the window's regions, opaque
  background, header per selection, map inset opening the full map and a pin
  click selecting a boss, placeholder text, one-letter search, and everything
  the first window's specs covered that still applies.
- Data spec: every map's cells are in range, every pin is within 0 to 1.
- In game, by the player: the look of it.
